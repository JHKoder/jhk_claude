핵심 용어

Run — Claude가 하나의 실험 과제를 완료한 세션 전체. 테이블의 #번호가 Run ID입니다. Turn — 하나의 Run 안에서 Claude가 응답한 횟수. 타임라인 슬라이더 단위입니다. BEFORE — 비교 기준 Run. [BEFORE] 버튼으로 지정하면 오른쪽 패널의 Δ 메트릭이 해당 Run 대비로 계산됩니다.

메트릭 읽는 법

  • Input 토큰 — 해당 턴에서 모델이 읽은 전체 컨텍스트 크기
  • Output 토큰 — 모델이 생성한 응답 분량
  • 캐시 히트율 — 이전 컨텍스트가 캐시에서 재사용된 비율 (높을수록 비용 절감)
  • 추정 비용 — 모델별 단가(Opus / Sonnet / Haiku)로 자동 계산한 턴당 USD

모델 배지

  • ■ Opus — 고성능, 고비용 (기본 $15/M input)
  • ■ Sonnet — 균형형 (기본 $3/M input)
  • ■ Haiku — 저비용 분석용 (기본 $0.25/M input)

Before / After 비교

두 Run의 토큰·비용 차이를 즉시 확인하는 워크플로우입니다.

단일 비교

  • 테이블에서 기준 Run의 [BEFORE] 버튼 클릭 → 해당 행에 주황 테두리 표시
  • 비교할 Run 행 클릭 → 하단 타임라인이 해당 세션으로 전환
  • 각 카드의 ▼ Δ 배지가 BEFORE 런 평균/턴 대비 증감을 표시

1~N 순차 비교

최신 Run을 AFTER로 고정하고, 이전 모든 Run을 순서대로 비교하는 방법입니다.
  • 카드 타이틀 옆 [1~N 순차 비교] 버튼 클릭
  • 스텝 바가 나타나면 [#1] [#2] … [#N] 버튼으로 BEFORE를 슬라이딩
  • 각 스텝마다 BEFORE가 교체되고 Δ 메트릭이 즉시 갱신
  • [BEFORE] 버튼 직접 클릭 시 순차비교 모드 자동 종료

행 클릭 확장 패널 표시 기준

행 클릭 시 확장 패널은 항상 열립니다. Before/After 수치 표시 여부는 아래 조건에 따라 다릅니다.
  • Before 수치 — 현재 Run보다 ID가 작은 Run이 존재할 때만 표시 (없으면 전체 —)
  • Δ 변화율 배지 — Before 값이 존재하고 Before 값 > 0 일 때만 ▼/▲ X% 표시
  • 비교 지표 4가지 — Output 토큰 · Cache Read · 비용(USD) · Turn 수
  • 현재 실험 상세 — Branch / Model / Runner / LOC+- / CLAUDE.md hash / Notes (항상 표시, 값 없으면 —)
  • 평점 버튼 — 항상 표시, 클릭 시 exp rate <id> <1-5>와 동일 효과

타임라인 리플레이

  • ▶ 버튼 또는 슬라이더로 턴 단위 재생
  • 차트의 현재 턴 바가 강조(불투명)되고 나머지는 흐려짐
  • 빨간 테두리 바 = 캐시 미스 감지 턴 (입력 토큰 급등)

exp CLI 명령어

실험 실행

# 기본 실험 (task-001) exp run my-exp claude # 특정 모델 지정 exp run opus-test claude task-001 --model opus exp run haiku-test claude task-001 --model haiku # 자유 프롬프트 플랜 실행 exp plan refactor claude "PaymentService N+1 수정"

결과 관리

# 실험 목록 확인 exp list # 단일 실험 상세 exp show 7 # 두 실험 비교 (텍스트) exp compare 5 7 # 평점 입력 (1~5) exp rate 7 4

분석 및 서버

# 프롬프트 최적화 분석 (Haiku 사용) exp analyze # 강제 재분석 exp analyze --force # 대시보드 서버 실행 exp serve # 기본 7788 포트 exp serve 8080 # 포트 지정

Stop Hook 자동 저장 조건

  • Turn count ≥ 5
  • Output 토큰 ≥ 500
  • git diff 파일 변경 있음

위 조건 미충족 시 자동 저장되지 않습니다. store.py의 insert()로 수동 삽입 가능.

.claude 아키텍처 명세

Anthropic Claude Code CLI 프로젝트 하네스 공식 사양 — 실무 적용 기준

1. CLAUDE.md 계층 구조

세션 시작 시 엔진은 아래 5개 계층을 탐색해 단일 컨텍스트로 병합한다. 하위 레벨이 상위를 덮어쓰는 것이 아니라 연쇄 추가 방식이므로 계층 간 모순은 엔진이 임의 선택할 수 있다.

계층 경로 범위 용도
Managed Policy /etc/claude-code/CLAUDE.md 조직 전체 IT/DevOps 중앙 강제 정책
User Memory ~/.claude/CLAUDE.md 개발자 전역 개인 코딩 스타일 · 워크플로우
Project Memory ./CLAUDE.md 프로젝트 전체 아키텍처 · 테스팅 · 네이밍
Directory Memory ./sub-package/CLAUDE.md 하위 디렉토리 서브 모듈 전용 규칙
Local Override ./CLAUDE.local.md 개인 로컬 .gitignore 처리, 로컬 실험 메모

병합 규칙

  • 같은 디렉토리에서 CLAUDE.local.md 내용이 CLAUDE.md 하단에 추가된다
  • 계층 간 모순 시 모델이 임의 지침을 따를 수 있음 → 거버넌스 수립 시 사전 충돌 방지 필수
  • 프로젝트 루트 CLAUDE.md 본문은 300줄 미만, 가급적 60–200줄 유지 (지침 과다 시 주의력 분산 + 토큰 비용 증가)

Auto Memory vs CLAUDE.md

구분 CLAUDE.md Auto Memory
관리 주체 엔지니어 직접 작성 Claude Code 자율 업데이트
내용 아키텍처 패턴 · 금지 지침 디버깅 패턴 · 에러 해결책
주입 방식 세션 시작 시 전문 로드 인덱스 상위 200줄 / 25 KB 자동 로드
인터페이스 텍스트 에디터 + Git /memory 커맨드 · # prefix

2. 모듈형 규칙 아키텍처

.claude/rules/는 CLAUDE.md 단일 파일 비대화를 막고 도메인별 가이드라인을 격리한다. 세션 시작 시 자동 탐색되어 컨텍스트에 합치된다.

.claude/ ├── rules/ │ ├── java-spring-rules.md # 백엔드 프레임워크 규칙 │ ├── java-code-style.md # 코드 콘벤션 │ ├── git.md # 커밋/브랜치 전략 │ └── openapi-conventions.md # API 문서화 규칙 └── hooks/
  • 구체적 행동 단위로 작성 — "코드를 정돈하라" ✗ → "2칸 들여쓰기 적용", "npm test 수행" ✓
  • ~/.claude/rules/*.md — 모든 프로젝트에 공통 적용되는 전역 개인 규칙
  • 로드 확인: 세션 내 /memory 커맨드로 로드된 파일 목록 점검

3. 라이프사이클 훅

확률적 프롬프트 지침과 달리 도구 실행 전후에 쉘 스크립트를 결정론적으로 실행하는 하네스 제어 메커니즘.

이벤트 트리거 시점 주요 역할
PreToolUse 도구 실행 직전 사전 검증 · {"decision":"block"}으로 차단
PostToolUse 도구 실행 완료 후 린트 에러 수집 · 다음 턴 컨텍스트 자동 수정
PermissionRequest 권한 승인 인터랙션 조건부 자동 승인 로직
PostToolUseFailure 도구 실행 실패 에러 로깅 · 복구 지침 주입
Stop 메인 에이전트 종료 종합 검증 · 테스트 · 릴리즈 체크 ← 이 대시보드 수집 시점
{ "hooks": { "Stop": [{ "hooks": [{ "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/collect_experiment.sh", "timeout": 120 }] }] } }

4. 스킬 시스템

마크다운 파일 하나 = 재사용 가능한 프롬프트 템플릿. 슬래시 명령으로 호출.

  • 위치: .claude/skills/<name>.md (프로젝트) / ~/.claude/plugins/ (전역)
  • 호출: /debug, /tech-analysis — 입력창 슬래시 prefix
  • skill 내 체크리스트 항목 → 에이전트가 TaskCreate로 자동 추적
